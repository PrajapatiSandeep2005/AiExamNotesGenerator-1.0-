AI EXAM NOTES GENERATOR - LOCAL SETUP
====================================

This file describes how to configure and run the project locally. Do not put
real secrets in source control or share them publicly. The .env files are
ignored by Git.

REQUIREMENTS
------------
- Node.js (use a current LTS release) and npm
- A MongoDB database (local or hosted, such as MongoDB Atlas)
- A Firebase project with Google sign-in enabled
- A Google Gemini API key
- A Stripe account and API keys for the current server implementation

ENVIRONMENT FILES
-----------------
Create two separate files: server/.env and client/.env.
Replace every placeholder below with your own values.

server/.env:

PORT=5000
MONGO_URI=mongodb+srv://<username>:<password>@<cluster>/<database>?retryWrites=true&w=majority
JWT_SECRET=replace_with_a_long_random_secret
GEMINI_API_KEY=replace_with_your_gemini_api_key
STRIPE_SECRET_KEY=sk_test_replace_with_your_stripe_secret_key
STRIPE_WEBHOOK_SECRET=whsec_replace_with_your_webhook_signing_secret
GROQ_API_KEY=replace_with_your_groq_api_key
CLOUDFLARE_ACCOUNT_ID=replace_with_your_cloudflare_account_id
CLOUDFLARE_AUTH_TOKEN=replace_with_your_cloudflare_api_token
CLIENT_URL=http://localhost:5173

Variable notes:
- PORT is optional; the server defaults to 5000. If you change it, update the
  frontend API address described below.
- MONGO_URI must point to a database your machine can access. For MongoDB
  Atlas, allow your current IP address and use the database connection string.
- JWT_SECRET must be a private, long, randomly generated value.
- GEMINI_API_KEY is needed to generate notes.
- STRIPE_SECRET_KEY and STRIPE_WEBHOOK_SECRET are needed for Stripe payments.
  The current code constructs the Stripe client when the server starts, so
  STRIPE_SECRET_KEY must be set even if you do not plan to test payments.
  For local webhook testing, get STRIPE_WEBHOOK_SECRET from the Stripe CLI
  listener command shown below.
- GEMINI_API_KEY is used by Gemini. GROQ_API_KEY, CLOUDFLARE_ACCOUNT_ID, and
  CLOUDFLARE_AUTH_TOKEN are optional and enable those providers and automatic
  fallback. Keep all provider keys in server/.env; never put them in client/.env.
- CLIENT_URL should be the frontend's origin (normally
  http://localhost:5173); it is used for CORS and payment return URLs.

client/.env (optional):

VITE_FIREBASE_API_KEY=replace_with_your_firebase_web_api_key
VITE_API_URL=http://localhost:5000

The Firebase configuration's project ID and other settings are currently
hard-coded in client/src/utils/firebase.js. The API key above must belong to
that Firebase project, or update the hard-coded Firebase configuration to
match your own project. Enable Google as a Firebase Authentication provider
and allow localhost in the Firebase authorized domains.

FRONTEND API ADDRESS
--------------------
In development, the frontend defaults to http://localhost:5000. Set
VITE_API_URL in client/.env to override this (for example, to use the hosted
backend). In production, the frontend defaults to the hosted Render backend.
If you change the backend PORT, update VITE_API_URL to match and restart Vite.

When using the hosted backend from localhost, its deployed CORS configuration
must allow http://localhost:5173. Redeploy the backend after changing
server/index.js; local source changes do not update the Render service.

INSTALL DEPENDENCIES
--------------------
Run these commands from the repository root in PowerShell or a terminal:

cd server
npm install
cd ..
cd client
npm install

RUN THE APP
-----------
Open two terminals from the repository root.

Terminal 1 - backend:
cd server
npm run dev

Terminal 2 - frontend:
cd client
npm run dev

The Vite development server is normally at http://localhost:5173.
The backend is normally at http://localhost:5000. Opening the backend root
URL should return a JSON message confirming that the backend is running.

OPTIONAL: TEST STRIPE WEBHOOKS LOCALLY
--------------------------------------
Install and authenticate the Stripe CLI, then run:

stripe listen --forward-to localhost:5000/api/credits/webhook

Copy the signing secret printed by the CLI (it starts with whsec_) into
server/.env as STRIPE_WEBHOOK_SECRET, then restart the backend. Use Stripe
test-mode keys while testing.

TROUBLESHOOTING
---------------
- If the backend cannot connect to MongoDB, check MONGO_URI, database
  credentials, network access, and Atlas IP allowlisting.
- If browser requests fail, confirm the client API address points to the
  backend, CLIENT_URL matches the browser's frontend origin, and the deployed
  backend's CORS allowlist includes that origin.
- If local sign-in succeeds but refresh signs you out, restart the backend
  after updating it so it uses the development cookie settings. For a hosted
  deployment, set NODE_ENV=production and redeploy to enable secure,
  cross-site authentication cookies.
- If Google sign-in fails, check the Firebase API key, Google provider
  configuration, and authorized domains.
- If note generation fails, check GEMINI_API_KEY and the server logs.
- If Groq or Cloudflare generation fails, verify GROQ_API_KEY,
  CLOUDFLARE_ACCOUNT_ID, and CLOUDFLARE_AUTH_TOKEN in server/.env, then restart
  the backend. Configure Cloudflare tokens with permission to run Workers AI.
- If Stripe checkout or webhook handling fails, check both Stripe secrets,
  use test-mode credentials, and confirm the webhook forwarding URL.
